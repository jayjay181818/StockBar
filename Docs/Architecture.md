# Stockbar architecture

Reference material; read the relevant section when needed. Shared working instructions are in [AGENTS.md](../AGENTS.md). Implementation details may change; inspect the linked source of truth before relying on exact values.

## Architecture Overview

macOS portfolio tracker with Swift/Python integration. `LSUIElement = false`: the app has a Dock-visible window and menu bar controls.

### Lifecycle
`main.swift` → acceptance preflight hooks → `AppDelegate` → `StockMenuBarController` (owns `DataModel`, `StockStatusBar`, and `StockbarMainWindowController`).

`main.swift` intercepts `--acceptance-preflight` / `--acceptance-bootstrap` and exits before `NSApplicationMain` — keep that block first.

### Data flow (MVVM + Observation)
```
DataModel (@MainActor @Observable)        central state hub
  ├── realTimeTrades: [RealTimeTrade]             ← drives menu bar + all views
  ├── RefreshService                              ← refresh scheduling; RefreshPassScheduler serializes passes
  ├── CacheCoordinator (actor)                     ← TTL + backoff + circuit breaker
  ├── PythonNetworkService → python3 subprocess → get_stock_data.py
  ├── Trading212BrokerSyncService / Trading212Provider   ← broker-linked holdings
  ├── FolyncPortfolioSource / FolyncSupplementalData     ← self-hosted portfolio source
  └── Core Data (historical prices, OHLC, snapshots) + UserDefaults
```

Shared models (`DataModel`, `RealTimeTrade`, `HistoricalDataManager`, `CurrencyConverter` and the shared services) use `@Observable`, so SwiftUI redraws only views that read the property that changed. Internal state that views must not track is `@ObservationIgnored`. AppKit and service code subscribes through `ObservationPublisher` (`Utilities/ObservationPublisher.swift`), which replaces `$property` publishers. View-owned chart view models stay `ObservableObject` with `@StateObject`, which builds them once per view.

### Portfolio sources (mutually layered, not alternatives)
Three sources coexist and must stay non-destructive to each other:
1. **Local/manual** trades in UserDefaults + Core Data — the base layer, always preserved.
2. **Trading 212** — broker-linked holdings; linked positions take quantity/price/avg-cost/P&L from the broker and deliberately *skip* market-data providers. Credentials live in Keychain only. Read-only; no order execution.
3. **Folync** — a self-hosted instance acting as authoritative read-only portfolio source. When active, `legacyPortfolioTrades` holds the shadowed local portfolio so switching back restores it. Folync-backed financial fields are read-only; watchlists, alerts, and menu-bar prefs stay Stockbar-owned. Supplemental routes (line history, OHLCV, benchmarks, FX) are independently toggled and **never splice Folync and legacy points into one series**. Net deposits for the "Measure P&L Against" setting come from the last `netContributionSeries` point of Folync's `3m` portfolio history, read at most every five minutes and only for the snapshot's own scope and currency (a stale cached history is never used; a figure is kept for up to fifteen minutes while Folync does not answer); `DisplayPortfolioSummary.totalGain` keeps its cost-basis meaning, and `totalReturn(measuredAgainst:)` chooses between the two. The portfolio chart (popover and Overview) first draws the history saved from Folync's last full answer for that range (`savedPortfolioHistory`, a disk read with no request or Keychain read, used only if Folync confirmed it with a full answer or a 304 within the last day), labelled "Checking Folync", then replaces it with what `routePortfolioHistory` returns; it still makes one conditional request per load. When the request fails with nothing usable saved, `routePortfolioHistory` returns `.unreachable` when no HTTP response arrived (a timeout, lost connection or TLS failure) or a gateway answered 502/503/504, and `.unavailable` otherwise, so the views can say "Couldn't reach Folync" rather than asking for more stored history; a saved copy returned as `.stale` sets `folyncStale`, and the Overview's period change then says "No current history from Folync"; `HistoricalDataManager` keeps `.unreachable` portfolio series in `folyncUnreachableSeries` with the coverage label "Couldn't reach Folync", so the Charts page gives the same reason beside its "Unavailable" badge; each range logs one warning when it starts failing (with `FolyncRefreshSchedule.failureCategory`) and one line when it recovers.

Folync's three ledger routes (dividends, trade analysis, transactions) are read by `FolyncSupplementalCoordinator.routeDividends`, `routeTradeAnalysis` and `routeTransactions`, with `loadMore…` for later pages; models, queries and results are in `Services/FolyncLedgerData.swift`. They have their own `FolyncLedgerRoute` enum, not `FolyncSupplementalRoute`, so the Settings screen and acceptance preflight do not list them, and their settings (`dividends`, `tradeAnalysis`, `transactions` on `FolyncSupplementalSettings`) default to on, since they are fetched only when a page asks; the capabilities keys for them are optional. Each route follows the portfolio-history pattern (settings, scope and capability gates, saved copy with ETag, 304, schema 2, stale copy, `.unreachable` against `.unavailable`; a 404 is `.unavailable` with no backoff). Because Folync rebuilds the whole report for each of them, unqueued, `FolyncLedgerFetchPolicy` sits in front of all three: one request at a time with identical requests shared, and a request still waiting its turn is never made once every caller waiting for it has been cancelled; page one reused for five minutes per endpoint, scope, route and query unless refreshed, and dropped from memory after that; later pages only on an explicit load more, never saved or reused; a 409, a refused cursor or a changed `page.collectionRevision` restarts from page one (the ETag changes too often to mean changed data). Null figures stay nil and unknown enum values are kept. Date parameters are `FolyncLedgerDay` values, not `Date`s, so a day chosen in the user's time zone is the day asked for. Nothing polls them.

The **Income** page (`Views/StockbarIncomeView.swift`) reads the dividends route through `StockbarIncomeModel` (`Views/StockbarIncomeModel.swift`), which reaches the coordinator through the small `StockbarIncomeRouting` protocol. It asks once when the page becomes the selected page (without `forceRefresh`, so the policy's five-minute reuse applies) and once per explicit refresh (with it); one query, all statuses with pay dates from twelve months back to twelve months ahead at the largest page, serves Outlook, History and By holding. Later pages come only from **Load more**, with the same query; `.restarted` replaces the rows. A newer request cancels the one in flight, and a result is applied only if its task was not cancelled and is still the latest, so a cancelled caller's `.unavailable` never shows. The headline, declared and estimated income, yields and received income are `summary` figures shown as given. The only figures the page derives, in `Analytics/IncomeFigures.swift`, are the chart's month sums and the By holding sums over the events listed, in the answer's currency; an event whose `portfolioAmount` is null, unavailable or in another currency adds nothing and is counted. Pay dates are read as calendar days, never through a `Date`. A bar's part comes from the event's `status` and its optional `discovery.amountCertainty`; an upcoming event without that detail is "to come", neither declared nor estimated. The sidebar entry carries the "New" badge and is dimmed for a portfolio that is not Folync's, which makes no request.

`InstrumentResolver` maps provider tickers (esp. Trading 212's) to canonical instrument identities; `SymbolMetadata` distinguishes benchmark symbols (`^GSPC`, `^FTSE`) from holdings, and `Trade.isWatchlistOnly` marks symbols with no position math.

### Python bridge
- `NetworkService` protocol → `PythonNetworkService`. The one other implementation, `BenchmarkQuoteService` (`Utilities/BenchmarkRefresh.swift`), gives made-up quotes to the benchmark's refresh workload (`Scripts/perf/benchmark.sh --refresh`); `DataModel` takes it only in an acceptance run with live providers off that asks for it. Process spawning isolated in `PythonProcessRunner`; interpreter/env in `PythonConfiguration` (the `pythonInterpreterPath` default, else Stockbar's own `python-env` in Application Support, even before it exists; there is no system-Python fallback). `PythonEnvironmentSetup` builds that environment by running the bundled `setup_python_env.sh` from Settings → Advanced → Python or the missing-package alert; `script/setup_python_env.sh` runs the same script from a checkout.
- `PythonWorkerPool` keeps up to two `stockbar_worker.py` processes running so `get_stock_data.py`, `get_ohlc_data.py` and `get_instrument_events.py` requests skip interpreter start-up and package imports. The worker runs the script in place with fresh globals and returns its stdout, stderr and exit code, so the script contract below is unchanged. When every worker is busy, or a worker fails, the request runs as its own process. Workers are replaced when the interpreter or environment changes, stopped after a timeout or cancellation, and exit when idle or when the app quits. An idle worker holds about 70 MB; with Settings → Advanced → Memory → Quit Python Helper When Idle on (`pythonHelper.quitWhenIdle`, on by default) it exits after 90 idle seconds, so it is kept for one refresh pass or backfill burst and not between refreshes, and with it off after 15 idle minutes (while markets are open, a one-minute refresh interval reuses its worker either way; closed London and US listings are refetched every 30 minutes, which outlasts both timeouts). The pool looks for idle workers every quarter of the timeout, so a worker lives up to a quarter longer, and reads the setting at each look.
- **Contract: JSON on stdout, human logs on stderr only.** Quotes use `get_stock_data.py --json <symbols…>`; also `--historical` and `--test-key`. Candles come from `get_ohlc_data.py`. Instrument events (Yahoo's instrument type, ex-dividend, pay and earnings dates, and twelve months of dividends in the major unit) come from `get_instrument_events.py --json <symbols…>`, one envelope per symbol; a field Yahoo does not give is `null` and past dates are returned as given. While it runs the script reads the process clock in UTC, because yfinance makes Yahoo's calendar dates in the local zone and a date stamped at midnight UTC would come out a day early west of UTC. Errors come back as a JSON envelope with `error: true` and `error_code`. (This is JSON parsing, not the old stdout regex.)
- `InstrumentEventsService` (`Services/InstrumentEventsService.swift`, nothing calls it yet) runs that script only when `StockbarProviderAccessPolicy` allows the Python bridge, once for every symbol missing or older than a day, with callers at the same time sharing the run. Answers are saved per symbol under Application Support/`InstrumentEvents` (atomic writes; copies older than thirty days removed). When Yahoo does not answer it returns the saved copy marked stale; after a rate limit it makes no run for an hour, and a symbol Yahoo has nothing for is not asked for again that day unless forced.
- Timeout values and batch sizing live in `Stockbar/Data/Networking/NetworkService.swift`; inspect the relevant operation when changing fetch behavior.
- Failed fetches return a placeholder `StockFetchResult` with `.nan` prices rather than throwing, so metadata survives.
- `PythonConfiguration.validateSymbol/sanitizeSymbol` restrict symbols to `A-Z0-9.^=-` to prevent argument injection — route new symbol paths through them.
- Providers inside the script: live quotes use a fixed order (yfinance, Twelve Data, then FMP); historical data follows `DATA_SOURCE_PRIORITY` (default yfinance, then FMP). Python-side quote cache at `~/Library/Caches/stockbar-cache/quote_cache.json` (passed by the app via `STOCKBAR_CACHE_FILE`, acceptance-aware; a legacy `~/.stockbar_cache.json` is moved there once), lock-file guarded with atomic replace.
- `ENABLE_USER_SCRIPT_SANDBOXING = NO` and the app must stay unsandboxed — the subprocess bridge depends on it. The entitlement validator checks app sandbox and server permissions and allows exactly one entitlement, which lets the ad hoc signed app load its Sparkle framework; the Xcode project defines script sandboxing.

### UI layer
- **Window**: `StockbarMainWindowController` hosts `Views/StockbarMainView.swift`: a see-through window with a floating sidebar panel (`Views/StockbarSidebar.swift`) beside the page. Thirteen sections in three groups, defined once in `StockbarMainSection.sidebarGroups`: Portfolio (Overview, Holdings, Activity, Alerts), Analysis (Charts, internally `charts`; Income, Trades, Risk, Allocation) and System (Data Health, Backups, Diagnostics, Settings). The sidebar, the **View** menu (`StockbarSidebarMenu.makeViewMenu`) and ⌘1–⌘9 (`shortcutNumber`) are all built from that one list, so they cannot drift apart; a section is added there only once its page exists. "Preferences" just opens the Settings section.
  - **Why the sidebar is custom**: in this AppKit-owned window macOS gives no floating sidebar (a unified toolbar on `NavigationSplitView`, an `NSSplitViewController` sidebar item and a background extension effect all gave the flat full-height one), so the app draws the panel and its entries, and rebuilds what the standard sidebar gave for free: one Tab stop with Up, Down, Home and End moving the selection and a focus ring on the selected entry; for VoiceOver, group headings and entries that read their title, any "New" badge (`StockbarMainSection.newSections`) or dimmed reason (`StockbarSidebarModel.groups(dimmed:new:)`; `folyncOnlySections` are dimmed with "Needs a Folync portfolio" unless the portfolio is Folync's), their position and their selected state; and hiding (`StockbarMainNavigationState.isSidebarHidden`, saved as `mainWindow.sidebarHidden`) through View → Hide Sidebar (⌃⌘S) and a toolbar button.
  - **Window backing**: the window is non-opaque with a transparent title bar; `StockbarWindowBackground` draws an `NSVisualEffectView` with behind-window blending under a light or dark wash, or an opaque window colour under Reduce Transparency. A unified toolbar moves the traffic lights onto the panel and holds the sidebar button. The button is a toolbar item because a SwiftUI button drawn on the panel at the traffic lights' height never received a real click, while page controls lower in the 52-point strip (the Overview's range switch, clicked at 37 to 52 points from the top) did, at the default and the minimum size; the cause is not established, so anything placed in the strip needs a real-click check. The window's minimum, 1060 by 680, is held by constraints on the content view rather than by the hosting controller, whose minimum adds the strip's height.
  - **Availability split**: `stockbarSidebarPanel()` uses `glassEffect` only behind `#available(macOS 26, *)`; macOS 15.4 to 25 get `.regularMaterial` with a hairline. `StockbarShellPanelStyle.resolve` chooses glass, material or solid and the stroke, and `stockbarGlassAvailableOverride` lets tests draw the fallback. Entry fills (`StockbarSidebarEntryStyle`) differ for selected, hovered and pressed, in both appearances.
  - **Footer**: `StockbarSidebarFooterStatus.make` turns the status the app already has (source, `folyncConnectionState`, the last poll's failure category, the saved snapshot's time, the last price update) into the footer's text; it makes no request. `.offlineCached` on a Folync portfolio turns it amber, and VoiceOver hears the change.
- **Overview**: `Views/StockbarOverviewView.swift` reads the same `PortfolioMenuChartViewModel` as the portfolio popover. It offers `StockbarOverviewView.offeredRanges(for:)` (1D, 1W, 1M, 3M, 1Y, All for every source), each served by the same `routePortfolioHistory` range or `loadPortfolioValuesFromCoreData` read as before; the popovers keep `MenuChartTimeRange.menuRanges`. The composition card is `PortfolioTotalComposition` (`Services/PortfolioCalculationService.swift`), built by `overview(summary:snapshot:netDeposits:)` only for a Folync portfolio: the snapshot's total, `profitLoss.unrealized` and `profitLoss.realized`, and `summary.netDeposits` with the currency of the history it came from. It is nil unless all four are known, not marked `unavailable`, and in the summary's currency; nothing is converted. Figures are held in whole pennies, rounded half to even as they are displayed, and the remainder ("Income, interest and fees") takes the rounding difference. The amber notice comes from `folyncConnectionState == .offlineCached` with a snapshot on screen, worded by `folyncLastPollFailureCategory`, and timed by the later of `folyncLastCheckedAt` and the snapshot's `generatedAt`.
- **Holdings**: `StockbarHoldingsView` in `Views/StockbarMainView.swift` draws the page; `Views/HoldingsTableSupport.swift` holds its pure parts: `HoldingsWeight`, `HoldingsText` (strip captions, the line under the table, each row's VoiceOver sentence), `HoldingsGainDisplayMode` (the one Amounts/Percent choice, stored under `holdings.gainDisplayMode`) and `HoldingsTableLayout`, whose editing columns fit the card at the window's minimum width. A row's weight comes from `DataModel.calculatePositionWeight(for:netValue:)`: Folync's `allocationPct` as given, otherwise the holding's value converted into the net value's currency as a share of `calculateNetValue()`. `DataModel.netGainsSource` says which figure `calculateNetGains()` gave, so the strip can word it. The table's cells read the Amounts/Percent choice from the environment, because a `Table` keeps its cells when only that choice changes.
- **Activity**: `Views/StockbarActivityView.swift` draws the page; `Views/StockbarActivityModel.swift` holds `StockbarActivityViewModel` and the row formatting. The page owns the view model, so it is rebuilt each time the page is selected. It reads `FolyncSupplementalCoordinator.routeTransactions` and `loadMoreTransactions` through `StockbarActivityTransactionsRouting`, only on activation (without forcing, so `FolyncLedgerFetchPolicy`'s five-minute reuse answers a quick return), on the refresh control (`forceRefresh: true`) and on Load more; there is no timer and no cache of its own. A change of kind, mode or ticker is debounced by 400 ms, cancels the task for the superseded query, and its result is dropped if the task was cancelled. The kinds are fixed sets of the route's actions (`StockbarActivityKind.actions`); the mode is always sent and the ticker trimmed and upper-cased, so the same choice is the same cached query. Every figure is the route's own: `portfolioAmount` (gross, nil shown as "–", partial or unavailable marked beside it), `quantity`, `price` and `priceCurrency`, `commission` and `tax` in the transaction's `currency`, and `adjusted`/`adjustedReason`. Stockbar derives only the amount's direction from the action (`StockbarActivityDirection`), the month from the row's own `yyyy-MM-dd`, and the wording; it sums nothing. Without a Folync portfolio it makes no request.
- **Trades**: `Views/StockbarTradesView.swift` draws the page; `Views/StockbarTradesModel.swift` holds `StockbarTradesViewModel` and `StockbarTradesText`. The view model (main actor, one cancellable task) reaches `FolyncSupplementalCoordinator.routeTradeAnalysis` and `loadMoreTradeAnalysis` through `StockbarTradeAnalysisRouting`, so tests stand in for it. It asks only on `activate()` (the page appearing), on the page's refresh control (`forceRefresh: true`) and on Load more; a switch change (All, Open, Partial, Closed map to the route's `status` all, open, partial, closed, at the largest page, 200) waits 400 ms and cancels the task it replaces; a result is applied only if its task was not cancelled and its query is still the one shown, because a cancelled caller is answered `.unavailable`. It keeps nothing beyond the page's life; reuse for five minutes is `FolyncLedgerFetchPolicy`'s. Only a Folync portfolio (`DataModel.isFolyncPortfolioActive`) asks; otherwise the sidebar entry is dimmed and the page explains. Every figure is Folync's: the strip is `stats.winRatePct` with `wins`/`losses`, `winRateVsSp500Pct` with `winsVsSp500`/`lossesVsSp500`, `totalTradeGain` (every lot, open and closed, whatever the switch shows) and this calendar year's `activity[].fees` with `feesPctOfAvgValue`; each row is a lot's `holdingDays`, `costBasis`, `totalGain`, `totalReturnPct` and `alphaPct` against its own `benchmarkName`, in Folync's order; the costs card is one `activity` period's `fees`, `buyValue`, `sellValue` and `turnoverPct`. `StockbarTradesText` only formats them; nil is "–".
- **Menu bar**: `StockMenuBarController` + `StockStatusBar`, one `NSStatusItem` per visible symbol, Combine-driven; also handles external-display polling for status-item visibility.
- **Portfolio popover**: `Charts/PortfolioMenuPopoverView.swift`, opened by `StockStatusBar.toggleMainPopover`. Top to bottom: `PortfolioMenuHeadline` (header line, the total as a `StockbarSplitFigure`, the change on the selected range), the graph (`MenuPopoverLineChart`, with a dotted "Yesterday's close" line on the Today range when the day's change is known), a `StockbarSegmentedControl` for Today, 1 week and 1 month, `PortfolioMenuMoversList`, `PortfolioMenuSummaryStrip` (total return beside net deposits or cost basis) and `MenuPopoverFooter`. The movers are always today's, from `DataModel.calculatePositionProfitLoss(for:)`, whatever the range; `PortfolioMenuMovers` orders them, sets the bars' scale and the accessibility text, and leaves out watch-list symbols, benchmarks and empty positions. The popover sizes to its content, so its height is bounded explicitly: `toggleMainPopover` passes the room below the menu bar on the item's screen (`PortfolioMenuPopoverHeight`), and the list shows at most twelve rows, fewer on a short screen, and scrolls inside the popover for the rest. The popover keeps the system's own popover background, which covers the arrow; Reduce Transparency, Increase Contrast's edge and the macOS 26 glass are left to the system, and Increase Contrast also strengthens the popover's secondary text (`StockbarPopoverText`). When it closes, `popoverDidClose` releases its content unless it is shown again by then, so a closed popover is not redrawn at each refresh and a close reported late cannot empty one that is open again.
- **Rolling digits**: a figure that rolls to a new value asks for it with `stockbarRollingDigits()` (`Views/StockbarDesign.swift`), never with `contentTransition(.numericText())` itself, which `Scripts/validate_invariants.sh` refuses anywhere else. The modifier leaves the transition out when the `figures.rollingDigits` setting (Settings → Advanced → Memory) is off. Each SwiftUI root that AppKit hosts (`StockbarMainView`, `MenuPriceChartView`, `PortfolioMenuPopoverView`) ends its body with `stockbarRollingDigitsSetting()`, which reads the setting once for the whole window or popover; a new root needs it too, or its figures roll whatever the setting says.
- **Surfaces**: a surface is anything drawn behind content to group it: a card, an inset panel, a metric strip, a notice bar, an empty state, a pill, a row's hover, selection or stripe, a chart callout, a sheet header, the track of a range switch. Views take every surface from `Views/StockbarDesign.swift` (`stockbarCard()`, `stockbarSurface(_:tint:)`, `stockbarInset()`, `stockbarPill()`, `stockbarRow(…)`, `stockbarCallout()`, `stockbarEmptyState()`, `StockbarMetricStrip`, `StockbarNotice`), which gives each a light and a dark value and makes it stronger under Increase Contrast and solid under Reduce Transparency; `StockbarSurfaceStyle.resolve` holds the numbers. The range, period and mode switches inside pages are `StockbarSegmentedControl`; pickers in Settings forms stay native. Main-window gains and losses use `StockbarPalette.signedOnSurface` (`gain`/`loss`, darker in light mode); the portfolio popover uses the same colours through `signedOnPopover`; menu-bar titles, the per-symbol popovers and other chart series keep the system green and red through `signed`. The popovers take their tiles, notices, pills and hover fills from the same surfaces. `Scripts/validate_invariants.sh` refuses a surface drawn from a raw colour or material anywhere else; a line that is not a surface ends with `// stockbar-surface-allow: <reason>`.
- **Charts**: Swift Charts — `PerformanceChartView`, `CandlestickChartView`, `MenuPriceChartView`. `PerformanceChartView` is split by concern: the main file holds state, loading and the line chart; `+Comparison`, `+Metrics`, `+Export` and `+Candlestick` hold those panels. On the 1 Day and 1 Week ranges `ChartTimeCompression` draws long gaps between points narrow; the line chart, its axis labels, zoom and `ChartInteractionView` all work in those plot times, and only labels and hover text convert back to real times.
- **History**: `HistoricalDataManager` is split the same way: the main file holds storage, snapshot recording and chart reads; `+Folync` holds the Folync overlay, `+PortfolioMenu` the menu-bar values, `+Retroactive` the recalculation of past days, `+Metrics` and `+Thinning` the helpers.

### Persistence
| Store | Location | Contents |
|---|---|---|
| UserDefaults | `com.stockbar` (via `StockbarRuntimeStorage.userDefaults`) | Trades, preferences, cache timestamps |
| Core Data | `<App Support>/Stockbar/StockbarDataModel.sqlite` | Historical prices, OHLC, snapshots — model selected by `Stockbar/Data/StockbarDataModel.xcdatamodeld/.xccurrentversion`; data migration flags in `DataMigrationService`; `CoreDataStoreRecovery` handles corrupt stores |
| Config JSON | `<App Support>/com.stockbar/.stockbar_config.json` | `DATA_SOURCE_PRIORITY` (auto-migrated from the legacy `com.fhl43211.Stockbar` path); FMP + Twelve Data keys an earlier version wrote here are moved to the Keychain on first use |
| Keychain | `com.stockbar.credentials` (one item, `CredentialVault`) | Persistent broker/Folync credentials and the FMP + Twelve Data keys, read and written through `Trading212CredentialStore`, `FolyncCredentialStore` and `MarketDataKeyStore`. One item means one macOS prompt after an update. Items earlier versions kept under `com.stockbar.folync`, `com.stockbar.trading212` and `com.stockbar.marketdata` are imported on first read and removed only after the new item reads back. The market-data keys are passed to the Python scripts as environment variables per run; acceptance fixtures use a separate restricted token file |

Settings export/import (`SettingsTransferService`) seals an allowlist of defaults (`SettingsTransferKeys`), the config-file keys and Keychain credentials, and for Everything a Core Data copy, into one AES-GCM `.stockbarexport` file (`SettingsTransferContainer`). Imports validate everything first, snapshot the current state, and roll back on failure. `CoreDataStoreTransfer` copies and replaces stores through `replacePersistentStore`, and keeps the live store read-only until relaunch.

### Caching & failure policy

`Stockbar/Services/CacheCoordinator.swift` owns freshness, retry intervals and circuit-breaker thresholds. Preserve that policy when adding fetch paths.

- Freshness follows the user's Main Refresh Interval (`RefreshService.freshnessInterval`); the Python quote cache is bounded to match through `STOCKBAR_QUOTE_CACHE_SECONDS` (set by `PythonConfiguration.load`). Each quote carries `fetchedAt`, when the script fetched it; a quote served from the cache keeps its original time, and the app uses it as the price's update time and for its history point.
- Symbols with recorded failures are governed only by backoff (`shouldRetry`) and the circuit breaker; `shouldRefresh` never returns true for them. The per-symbol popover exposes suspension state and Retry Now.

### Currency
`CurrencyConverter` (exchangerate-api.com, USD base) for USD/GBP/EUR/JPY/CAD/AUD. **Normalize GBX/GBp to GBP once at the provider boundary.** Preserve values already reported as GBP, including cost bases. Use reported currency and existing provider-specific fallbacks; a `.L` suffix alone is not evidence that a value still needs division. See `PythonTests/test_get_ohlc_data.py` for regression examples.

### Updates
`Services/AppUpdateService.swift` owns Sparkle's updater and the state `Views/UpdateSettingsSection.swift` shows in Settings → General. Sparkle downloads, verifies and installs; Stockbar only decides whether the updater runs (`UpdaterAvailability`: not in Debug builds, not in test or acceptance runs unless the feed is on loopback) and which builds it may see (`UpdateChannel`: the Testing channel also allows feed items marked `testing`; the Experimental channel reads a feed of its own and allows the items marked `experimental` there). The two feed addresses, public key and signature requirements are in `Stockbar/Info.plist`, which Xcode merges into the generated one. How builds and the feed are produced is in [development workflows](Development.md#release-builds-and-updates).
